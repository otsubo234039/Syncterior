# 図面を主役にするための要件整理

2026-11-11。利用者が「図面寄り」を採用する方針を選択したことを受けた整理。ここでの「採用必須」は図面化を進める際の要件であり、実装済みという意味ではない。未決定の仕様と、現在のコードで確認できる不足を区別する。この文書によるAPI・保存形式の変更はない。

## 図面モードへの方針更新（2026-11-11）

「2D図面を保存し、その図面から3Dを生成する」という依頼に合わせ、画像取り込みを図面への変換として整理した。今回の実装範囲は、新規作図、グリッドと壁・床・開口の編集、図面単独の保存・再読込、JSONファイル入出力、同じ形状からの3D表示、モード別UI。詳細と関連Issueへの影響は[図面モードの設計](drawing-mode.md)を参照する。

グリッドは最大辺10mまで0.25m間隔、4目盛ごとに太線。大きい間取りは最大辺40目盛以下になる間隔を選ぶ。自動吸着・パン・ズーム・家具記号・寸法線・複数案・サーバー図面保存は未実装で、以下の要件は今後の検討として維持する。

## 目的と表示の基本方針

利用者が、間取りを下絵に合わせて修正し、家具が収まる位置・向き・間隔を判断できる平面図を作る。2Dでは位置・寸法・境界を読み取り、3Dでは高さ・見え方・立体的な配置を確認する。同じ実寸モデルを使い、表示用の拡大率や装飾を形状へ混ぜない。

白系の背景、濃い壁、薄い床、簡略化した家具記号を基本とする。青い背景の青焼き風表示を必須とはしない。Floorplannerは白黒輪郭・色付き輪郭・材質表示等を分けており、Sweet Home 3Dは2D作図と3D表示を連動させる。参考にするのは読みやすさと操作の分担であり、既存製品の全機能の再現ではない。[Floorplanner公式マニュアル](https://cdn.floorplanner.com/static/brochures/FloorplannerManualEN.pdf)、[Sweet Home 3D公式ガイド](https://www.sweethome3d.com/users-guide/)

## 採用必須の要素

| ID | 要素 | 最低限の仕様・成立条件 | 現状との差 |
| --- | --- | --- | --- |
| A1 | 一様な縮尺と実寸外形 | 遠近のない平面表示。家具の幅・奥行き・回転、床・壁・開口の位置を3Dと一致させる。装飾・選択枠を占有範囲として扱わない | SVGの基礎はある。登録寸法と3D各部品の寸法の照合が必要 |
| A2 | 線と塗りの階層 | 壁を最も強く、家具外形を次に、寸法・補助線・グリッドを控えめにする。壁厚は実寸、輪郭の線幅と文字は画面上の読みやすさを保つ | 現在は壁線・家具四角形・一律の方向線が中心。統一した描画規則が必要 |
| A3 | 種類を識別できる家具記号 | 現在の8種類を名前だけに頼らず見分ける。外形は実寸のまま、枕・背もたれ・画面など必要な特徴だけを描く。未知の家具も外形と名前で表示できる | 全種類に同じ長方形と線を使っている |
| A4 | 壁・床・開口の正しい表現 | 壁厚・接続・開口位置と幅をモデルに従って描く。窓は平行線等の形でも識別できるようにし、扉と色だけで区別しない。未知の開き勝手を描き足さない | 扉は白い隙間、窓は青い帯。建具の詳細データはない |
| A5 | 測る対象が分かる寸法・計測 | 寸法線と端点を形状へ対応させる。外接寸法、内法、壁芯、開口幅、家具寸法、家具間隔を混同しない。任意2点の計測と形状を変える実寸補正を分ける | 幅・奥行きの画面端タグのみ。図面内の対象と結び付く寸法線・任意計測は未実装 |
| A6 | 読める文字と必要量の表示 | 室名・家具名・寸法の文字サイズを確保し、重なりを避ける。選択した対象の情報を確実に読めるようにし、タッチでも取得できる | 家具幅と名前の長さで文字を小さくしており、小家具は読みにくい |
| A7 | 下絵との比較と状態の区別 | 下絵の表示・濃さ・固定、認識候補と手直し結果の区別、未適用であることを示す。仮の床を確定した室形状と誤認させない | #50の専用画面に基礎あり。通常の平面図との描画・状態表現の統一が必要 |
| A8 | 図面を動かしても正確に編集 | パン・ズーム・全体表示。表示変換後もクリック・ドラッグ位置を一致させる。小さな部品にも操作できる当たり領域を設け、実寸外形とは分ける | パン・ズーム未実装（#51） |
| A9 | 操作モードと誤操作防止 | 家具配置・間取り修正・計測を区別し、編集中の対象を明示する。図面を固定して家具だけを動かせる。選択・フォーカス・無効状態を色だけに頼らず示す | 間取り修正は別ダイアログ。ロック未実装（#53） |
| A10 | 取り消せる編集と安全な確定 | Undo/Redo、Escによる中断、ドラッグのキャンセルと後始末。自己交差・開口重複・家具干渉などを適用時にも検証する。下書きだけでは確定配置・保存を変えない | #50内の局所履歴と検証はある。家具配置全体の履歴は#16 |
| A11 | 白黒・狭い画面でも読める表示 | 色をなくしても壁・開口・家具・選択を区別できる。狭い画面では全ラベルを無理に重ねず、選択時に詳細を読める。キーボード・フォーカスを維持する | レスポンシブUIと一部キーボード操作あり。記号と文字量の整理が必要 |
| A12 | 2D・3D・保存・共有の一貫性 | 表示切り替えで配置と選択を維持。視点・拡大率・レイヤー表示は各画面だけの状態。形状は既存の検証を通す。新しい共有データはAPI対応前に送らない | 基本規則は既存実装を継続。追加データは別途設計が必要 |

「必須」と「最初の一回で全て実装」は同じではない。今回のグリッド・線編集の後、寸法の意味と描画規則を決め、記号・操作を段階的に揃える。

## 最初に用意する家具記号

既存カタログの8種類に絞る。元の3Dモデルの見た目と照合し、既存のアイコン素材を転用して外形寸法を変えない。

| 種類 | 図面で残す特徴 | 向きの扱い |
| --- | --- | --- |
| ソファ | 座面、背もたれ、肘掛け | 背と正面を区別 |
| ベッド | マットレス、枕 | 頭側を区別 |
| ローテーブル | 天板の外形 | 対称な形に架空の正面線を付けない |
| デスク | 天板の外形と種類ラベル | 現在の3Dはテーブルと同じ構成。存在しない引き出しや正面を創作しない |
| 椅子 | 座面と背もたれ | 背を区別 |
| テレビ台＋TV | 台の外形と画面位置 | 画面の表側を区別 |
| 冷蔵庫 | 本体外形と扉側の目印 | 扉側のみ表示。開き方向や円弧は追加データがない間は描かない |
| フロアランプ | 簡略化した円形記号 | 対称な記号に正面を設けない。登録寸法と3D形状を先に照合 |

家具の記号、選択用の当たり領域、実際の占有外形は別物として扱う。記号を見やすくするために家具自体を拡大したり、当たり領域を衝突判定へ流用したりしない。

## 仕様を比較検討する要素

必須になる目的と、未決定の実現方法を分ける。以下の推奨案は比較・検証の出発点。

| 論点 | 選択肢・検討事項 | 推奨する出発点 |
| --- | --- | --- |
| 初期表示と2D/3D配置 | 初期表示を2Dへ変えるか。広い画面で同時表示するか | 初期2Dを候補とし、まず切り替え式を維持。同時表示は#56で別段階 |
| 建具の種類と開き勝手 | 開き戸・引き戸・折れ戸・窓の種類、吊元、開く側、開放角 | 最初は既存の扉／窓と不明状態。吊元等を保存できるようにしてから円弧を描く。#29と調整 |
| 平面図に出す高さの範囲 | 建具の切断位置、吊り戸棚・高窓・梁・上下に重なる家具の表現 | 階層や高さで見え方が変わる対象は破線・別表示を検討。全対象を同じ実線で重ねない |
| 寸法の基準と表示精度 | 内法／外法／壁芯、m／mm、丸め、小数桁 | 計算は既存のm。表示はmを初期案にし、何を測った値か明記。内法自動寸法は壁面の計算が整ってから。読取精度を超える桁を出さない |
| スナップとグリッド | グリッド・水平垂直・端点・壁面・家具への吸着。許容距離と優先順 | ON/OFFと一時解除を提供。吸着先の予告を表示し、画面上の距離で許容範囲を調整。吸着しない自由移動も維持。#20 |
| 壁の接続と形状変更 | 接続点を共有するか。壁端点移動時に隣接壁も動かすか。壁厚変更の基準側 | 接続を保つ操作と切り離す操作を区別。認識候補の近接点を無条件に結合しない |
| ラベルの出し方 | 全常時表示、選択時のみ、拡大率による省略、外側への引出線 | 室名と主要寸法を優先し、小家具は選択時の詳細へ。省略しても選択と名前の確認は可能にする |
| 床・部屋の作り方 | 手動多角形、閉じた壁から自動生成、部屋名と用途 | 既存の床頂点編集を先に整える。閉ループ・開口・複数床を扱う自動室生成は別段階 |
| 下絵の再読込と整列 | 画像再選択、端末内永続化、回転・移動・原点・複数画像 | 現行は再選択と固定表示。回転等は2点の実寸補正との対応を定義してから。外部保存・送信は別要件 |
| 動線・扉開閉・重なり | 必要な通路幅の目安、家具同士の重なり、扉の可動域 | 寸法を測れることを先行。警告の基準と例外を定義し、根拠のない通路幅や建具可動域を断定しない。#14/#29/#30 |
| 出力と印刷 | SVG・PNG・PDF、用紙、印刷縮尺、白黒、凡例 | #22でSVG/PNGを候補とする。画面のズーム率と紙の1/n縮尺を分ける。取り込みUIへ1/n入力を戻さない |
| 方角・設備 | 方角、窓・コンセント、固定設備の記号と凡例 | #48/#44と合わせてモデルを整備。画像の上方向を自動で北としない |
| 図面データと共有 | 注釈・部屋名・吊元・ロック等の保存先と権限 | 表示状態と共有する設計データを区別し、新しいフィールドは保存版・検証・API契約を揃える。#38/#43 |

## 現在のコードから分かった優先課題

1. `plan-view.jsx`は全家具を同じ長方形と一本線で描く。家具種類別の記号と、3Dの向きに一致した特徴線へ置き換える必要がある。
2. 家具名の文字サイズが家具の幅と文字数に依存し、小さくなり続ける。画面上の最小サイズ・省略・選択時詳細を設計する必要がある。
3. 幅・奥行きのタグは対象に接続されておらず、内法か壁芯かも示していない。`floorPlanBounds`も床点と壁の端点から取る範囲で、壁厚を含んだ建物外寸とは限らない。測定基準を決めてから寸法線へ置き換える。
4. 取込形状の開口データは`kind/offset/width/bottom/height`のみ。吊元・開く側・引き戸等の種別がなく、扉の開閉円弧を描く根拠はない。
5. プリセットの`plans.js`には`doors`があるが、現在の`room.jsx`と`plan-view.jsx`の壁描画には使われていない。2Dだけに扉を追加せず、3Dとの形状の一貫性を整備する必要がある。
6. 例としてランプはカタログの幅・奥行き0.32mに対し、3Dのシェードの半径が0.17m（直径0.34m）。冷蔵庫の取手も本体から出ている。図面だけを整える前に、登録寸法・描画外形・境界判定に何を含めるかを照合する。
7. 通常の平面図と手直し画面で座標原点・壁の描画・選択の見せ方が異なる。画面構成をすぐ一つにする必要はないが、座標変換と記号のルールを共通にする。
8. 個人編集の初期表示は図面モードへ変更した。家具配置側の`PlannerCanvas`は3Dを初期表示し、平面図へ切り替えられる。共有リンクでは図面モードを開かない。

## 今回の範囲に続く実装段階と完了条件

### 第1段階: 図面の表示基盤

- 外形・寸法の基準と、壁／家具／補助情報の表示規則を決める。
- 8種類の家具記号を作り、名前・向きを確認できるようにする。
- パン・ズーム・全体表示、小さな対象の選択と読みやすいラベルを整える。
- 下絵と通常の平面図で同じ位置・向き・外形が使われることを確認する。

### 第2段階: 寸法と編集

- 任意の2点、家具、開口の寸法から始め、対象に接続した寸法線を提供する。
- 図面／家具／計測の操作を明示し、ロックと履歴を整える。
- スナップのON/OFF・解除を用意し、開口を塞ぐ結合や別位置への飛びを防ぐ。
- 壁面の計算と接続ルールを整えてから、室内の内法寸法を自動表示する。

### 第3段階: 建具情報と共有・出力

- 開き勝手・種類・高さの表現とモデルを設計し、2D/3Dへ反映する。
- 必要な保存形式・API契約の検証を揃えてから新しい図面情報を共有する。
- 出力、複数案、同時表示を追加する。

最低限の検証は、8家具×0/90/180/270度、壁際と開口付近、斜壁・凹形床、ズーム後の選択・ドラッグ、白黒での識別、ラベル重複、小家具、デスクトップ／モバイル幅、取消・保存復元、2D/3Dの一致。表示変更だけで保存や相手の視点が変わらないことも確認する。

既存Issueは#19（表示）、#50（手直し）、#51（ナビゲーション）、#52（計測・注釈）、#53（ロック）、#16（履歴）、#20（スナップ）、#22（出力）、#29（扉）、#43（形状共有）を参照する。今回の洗い出しだけで完了扱いにせず、追加実装時に実装範囲と検証を明記する。
