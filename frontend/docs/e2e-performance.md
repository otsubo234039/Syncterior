# E2Eの改善実験

Codespaces上のChromium / SwiftShaderで比較しました。各条件は単回の計測で、CPU負荷により変動します。代表4ケースは3Dドラッグ、初期配置、2画面同期、存在しない部屋からの復帰です。

| 条件（代表4ケース） | 時間 | 判断 |
| --- | ---: | --- |
| 常時描画・全ケース実WebGL・2回ビルド | 175.7秒 | 比較元 |
| 変更時だけ描画、その他は同じ | 77.5秒 | 採用 |
| さらに影を2048→512、接触影を低品質化 | 72.5秒 | 不採用。効果が小さく、2画面同期は改善せず |
| 変更時描画、UI/3D分離、元の影品質、2回ビルド | 61.1秒 | 分離を採用 |
| 同じ分離構成、1回ビルド、1 worker | 49.8秒 | 採用。ビルド9.6秒＋Playwright40.2秒 |
| 同じ4ケースを2 workers | 46.5秒 | 全体の差は小さく、各ケースは遅くなるため3D並列化は不採用 |

最初の4条件はPlaywrightのサーバー起動内にビルドを含みます。後の2条件はラッパーがビルドするため、`run-timing.json`の合計で比較しています。Playwrightの実行時間だけを比較するとビルド時間を落としてしまいます。

GPU指定を外す案も確認しましたが、指定あり・なしともANGLEのSwiftShader Deviceを使用しました。この環境ではハードウェアGPUへの切り替えにならないため、再現性のある明示指定を維持します。

UIのみ18ケースも1 workerで149.4秒、2 workersで151.1秒（いずれもビルド込み）となり、並列化の短縮効果は確認できませんでした。既定は1 workerを維持します。

UI18ケースのトレースを無効にした比較では117.0秒（ビルド10.3秒＋Playwright106.7秒）でした。常時記録の149.4秒より約22%短いため、既定を`on-first-retry`にしました。CIでは既存の1回の再試行でトレースを残します。ローカルでは`--trace=retain-on-failure`を指定して調査します。失敗時スクリーンショットは維持しています。

## 維持する条件

- `frameloop="demand"`で静止時の描画を止めます。実キャンバスの描画回数と画像変化により、家具の位置・色・回転・削除・視点操作時の再描画を検証します。停止の確認は初期表示・家具操作の間に行います。OrbitControlsの慣性移動中は描画が必要なため、ポインターを離した直後を静止状態とは扱いません。
- UIシナリオは遅延読み込みした3Dモジュールだけを置換します。Reactの状態更新やHTTP/SSEは実行し、置換の適用も確認します。
- 実WebGLを使用する専用プロジェクトでドラッグと2画面同期を残します。UIだけの成功で3Dの成功を主張しません。
- API有効・無効の画面は同一ビルドを使用します。起動前の公開設定で切り替え、毎回ビルドするため古い生成物は再利用しません。
- 影の品質を落としたり、失敗をskipやリトライ増加で隠したりして短縮しません。

## 再計測

`frontend/`で`npm run test:e2e`を実行します。`test-results/run-timing.json`にビルド・Playwright・合計を記録します。比較時はケース、ブラウザ、worker、トレース設定を揃えてください。`--workers=1`と`--workers=2`で並列度を比較できます。3Dだけなら`--project=3d --no-deps`を追加しますが、最終確認は通常コマンドで全件実行します。

計測はテスト専用APIによるものです。実バックエンド・AWS・実機GPUの性能を示すものではありません。

## 最終確認

採用した設定で通常の`npm run test:e2e`を実行し、UI18ケース＋実WebGL4ケースの全22ケースが成功しました。ビルド9.5秒、Playwright213.2秒、合計222.7秒でした。代表4ケースやUIのみ18ケースとは対象が異なるため、直接の短縮率比較には使いません。ローカルでの結果であり、GitHub Actions上の実行は未確認です。
