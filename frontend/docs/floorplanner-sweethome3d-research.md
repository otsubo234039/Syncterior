# Floorplanner・Sweet Home 3Dの機能調査

調査日: 2026-11-10。公式機能一覧・操作マニュアル・更新情報・API資料を確認した文献調査。製品へのログイン、契約、2アカウントでの同時編集の実測は行っていない。「公式資料で確認できない」を「存在しない」とは扱わない。

## 結論

Syncteriorに優先して取り入れたいのは、下絵と認識結果を重ねた平面編集、壁・開口の手動修正、距離の計測、パン・ズーム・全体表示。現在の自動抽出を、人が直せる下書きとして使う方向が適している。

両製品とも下絵取り込みは確認できるが、標準機能としての画像からの壁・開口の自動認識は今回確認できなかった。Floorplannerの共同編集用アクセス提供は確認できるが、同時操作の即時反映や競合解決は未確認。Sweet Home 3Dの公式記事ではリアルタイム共同編集を将来の可能性として扱っている。

Floorplannerの「real-time 3D view」やSweet Home 3Dの「2D変更を同時に3Dへ反映」は、1人の画面での表示更新を指す。ネットワーク越しの複数人編集の証拠にはならない。

## 取り込み操作の参考になる点

### Floorplanner

下絵を読み込み、傾きを回転補正し、既知の2点と実長で縮尺を合わせ、部屋ごとに壁をなぞる。下絵の表示や透明度を調整できる。壁への扉・窓の配置と、その寸法・高さ・扉の向きの編集を提供する。[F1]

Syncteriorでは2点による実寸補正をすでに実装しているため、縮尺合わせを新たに作り直す必要はない。認識結果の壁線と元画像を比較し、欠落・誤認識だけを平面図で修正できるようにする価値が高い。

### Sweet Home 3D

下絵の縮尺・原点を設定した後、2Dで壁を描き、扉・窓を壁へ置く。開口の穴はソフト側で生成する。床は多角形を描くか、閉じた壁で囲まれた場所を指定して作る。[S1,S2]

Syncteriorの自動抽出では床は仮の長方形なので、まず床の頂点を手で修正できることが有用。壁から部屋を自動生成する方式は、壁の接続・閉ループの判定が必要なため、その次の段階とする。

## 共同編集について確認できた範囲

Floorplannerの旧公式マニュアルには、アカウントを持たない相手にも14日間の編集アクセスを渡し、保存結果が元プロジェクトへ入る説明がある。[F2] ただし旧仕様のため、現在の期限・対象プラン・アカウント要否を確定情報として採用しない。現在のTEAMページで確認できるのは、複数ユーザー・役割・共通リソース等の管理機能。[F4] 埋め込みAPIにもプロジェクト単位のアクセストークンがあるが、これ自体は同時編集プロトコルではない。[F5]

Sweet Home 3DのOnline版は保存先がサーバーという意味でオンライン。公式の将来予測記事では、複数ユーザーのリアルタイム共同編集・履歴・端末間同期を今後の可能性として述べている。[S4] 今回の資料では標準機能として確認できない。派生版や独自プラグインの全調査は行っていない。

Syncteriorでは、家具・間取りの確定状態を共有し、視点・選択・表示モードは各画面に保持する現方針を継続することを提案する。閲覧リンクと編集リンクの分離、期限・無効化、個人ごとのUndoは今後の検討項目であり、今回確認した両製品のリアルタイム仕様をそのまま再現する提案ではない。

| 中 | 家具の複製・グループ | デスクと椅子等をまとめて移動・複製 | 個々の家具の境界判定と、共有時のまとめ操作の整合が必要 |

おすすめの順序は「パン・ズーム → 下絵重ね表示 → 壁・床・開口の手修正 → 計測・Undo → 配置案比較」。自動認識の精度向上だけに依存せず、利用者が修正して完成できる流れを先に整える。

共同編集の実サーバーは未実装。提案を具体化する際は既存のBE-07 / #38（認証・共有権限）、BE-11 / #43（取込形状の共有）を参照する。追加調査後に改善案を#50〜#56へ起票した。グループ操作に必要な追加APIは#55（backendラベル付き）で追跡し、BE-12へ記録した。現在のAPI契約・認証方式は変更していない。

## 外部製品そのものの組込み

Floorplannerは埋め込みAPIを提供するが、公式資料ではEnterprise契約・APIキーが必要で、編集領域は最低1000×800pxとされる。[F5] モバイル対応する現在の自前エディターへの小さな部品追加としては適さないと判断する。まず操作・仕様を参考にして自前のモデルへ実装する方が既存の構成に合う。

Sweet Home 3DはGPLで公開されるソフトウェア。[S2,S3] 今回はコード・家具素材の転載や組込みではなく操作設計を参考にする提案。家具素材やソースを直接利用する場合は、それぞれの配布条件と対象バージョンを別途確認する。

## 手直し実装の検証（2026-11-11）

`feat/#19` の未コミット変更で、本番ビルド、ユニットテスト、通常の `npm run test:e2e --prefix frontend` 全85件が成功。E2Eはデスクトップ幅・モバイル幅のUIと実Canvas/WebGLを含む。下絵の濃さ・表示、壁・床・開口の編集、取消と手直し履歴、保存復元、不正画像・形状と家具干渉の拒否、ドラッグ中断、3Dへの反映を確認した。モバイル幅の表示も画像で確認。実機タッチ操作、他ブラウザ、GitHub Actions、実バックエンドとの結合は未確認。

追加の依存パッケージとAPI契約の変更はない。元画像と手直し履歴は保存せず、確定形状と家具だけを既存の第2版で保存する。パン・ズーム、下絵の回転・位置調整、開き勝手や開口高さのフォーム編集は未対応。
