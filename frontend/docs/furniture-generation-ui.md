# 画像から家具モデルを作成するUI（Issue #45）

## 現在の動作

個人編集の「3D・家具配置」→「画像から家具を作成」で、同じ家具の写真1〜4枚と名前を入力する。1枚目を正面として扱い、残りは任意の別角度の写真とする。JPEG・PNG・WebP、1枚10MB以下、各辺32〜8192px・合計2000万画素以下。画像は追加・削除でき、正面を削除すると次の画像が1枚目になる。作成時には寸法を入力せず、サイズ調整は今後の家具全体の機能として別に扱う。

生成サービスとバックエンドは未実装。画像と有効な名前を入力すると作成ボタンを押せる。接続関数が未設定の場合は通常の作成失敗メッセージを表示し、画像を送信する通信は発生しない。画面には「準備中」「試作」「未接続」やサンプルの案内・操作を置かない。

接続後の生成結果は既存のGLB制限（20MB・10万三角形・埋め込み画像最大2Kなど）を検証し、プレビューで向きを確認して「この家具を配置」を押した時だけ確定する。入力寸法での拡大縮小は行わず、向き変更時にはその向きの外形を計測し直す。モデルの寸法が配置可能な0.02〜20mから外れる場合は、自動で変形させず拒否する。写真、生成待ち、進捗は配置JSON・図面保存・共有へ混ぜない。配置後のモデル保存は従来のIndexedDB、第3版の個人配置を使う。既存の手動GLB取り込みの寸法調整は維持する。

処理中は入力を無効にし、取消を提供する。画像読み込みの取消・差し替え、モード・間取り・共同編集状態の変更、アンマウント後に古い結果を適用しない。画像の表示用object URLとImageBitmapは解放する。ブラウザで処理を中止しても、将来のサーバー上のジョブの取消・返金を保証するものではない。

## 接続口

機能の公開入口から使う`RoomPlanner`に、`generateFurnitureModel`関数を渡す。未指定の場合も通常のUIを表示し、作成要求にはエラーを返す。状態は`useRoomPlanner`が内部で呼ぶ`useFurnitureGeneration`、入力・結果・進捗の検証は`utils/furniture-generation.js`に配置する。

```js
// 型の説明。HTTP APIのパスやジョブ形式を確定するコードではない。
async function generateFurnitureModel(request, { signal, onProgress }) {
  // request.images: File[]（1〜4枚、先頭が正面、元画像）
  // request.name: string（1〜80文字、trim済み）
  // signal: AbortSignal（画像送信・状態照会・GLB取得に渡す）
  // onProgress({ phase: 'queued' | 'running', progress?: number })
  // 進捗が取得できない場合はprogressを省略。UIは架空の進捗を作らない。

  // 自前バックエンドへ送信し、完了を待ち、GLBを取得する。
  // エラー時は利用者向けのmessageを持つErrorでrejectする。
  // 成功時:
  return { file: new File([glbBytes], 'furniture.glb', { type: 'model/gltf-binary' }) };
}
```

接続関数側でアップロード、認証、ジョブID、ポーリング／通知、待機間隔、タイムアウト、重複送信防止、結果の取得を扱う。UIは`queued`・`running`→GLB確認→プレビュー、または失敗を表示する。結果を配置せず、名前を引き継いだ未確定の取り込み候補にする。取消に応答しない接続関数でも待機を終了し、遅い結果・進捗は破棄する。再試行は利用者が押した場合だけ行う。

Meshy／Tripoの選択、モデルバージョン、利用料、HTTP APIのURL・認証方式・保存期間は未決定。ブラウザから生成サービスへ直接接続する設計や、APIキー入力欄は追加していない。サービスの秘密情報・署名URLを配置の参照にしない。返却ファイルは事前検証へ必ず渡し、不適合なら接続側で軽量化・画像埋め込み・形式変換の対応範囲を検討する。

共有家具への拡張は対象外。現行の共有作成・snapshot・共同編集への取込家具の混入拒否を維持する。サーバーの画像→3D対応は[バックエンド未実装項目](../../backend/docs/implementation-backlog.md)で追跡する。

## 検証範囲

- `utils/__tests__/furniture-generation.test.js`: 入力境界、画像の解放、接続関数への受け渡し、進捗・GLB結果検証、失敗・取消・遅延結果。
- `e2e/furniture-generation.spec.js`: デスクトップ／モバイル幅で画像追加・削除、入力検証、寸法入力・補足ラベルの不在、接続未設定時の失敗表示・非送信と入力保持、取消・モード切替、表示URL解放。
- 既存の`furniture-model.3d.spec.js`: GLBの実WebGL表示・家具操作。生成結果も同じ検証・読み込み・配置処理へ合流する。

これらはローカルの画像操作・自作GLB・テスト用接続関数による検証であり、外部生成サービスの品質・料金・速度、実APIや実バックエンドとの結合の検証ではない。生成接続後の画面操作はサービス選定・アダプター実装時に結合検証する。
