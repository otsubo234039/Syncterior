# 図面モードの設計とIssueへの影響

2026-11-11。利用者の方針「間取り画像の取り込みは図面への変換、2D図面を保存してその図面から3Dを生成する」に基づく実装。図面モードの実装とローカルでの検証結果をまとめる。CI・実バックエンドとの結合は未確認。

## データと操作の流れ

```text
画像 → 端末内で壁候補を抽出 → 一辺の実測で補正 → 図面へ変換
                                                   ↓
新規作図・JSON読込 ─────────────────────────→ 編集中の2D図面
                                                   ├→ 図面を保存 → ブラウザ内保存
                                                   ├→ JSONファイルを書き出す
                                                   └→ 図面から3Dを表示 → 家具配置
```

図面は `floor-plan.js` の実寸モデルで、壁端点・厚さ・高さ、床多角形、開口の位置・幅・下端・高さを持つ。SVGは2D描画、Three.jsのメッシュは3D描画で、どちらも保存データの本体ではない。単一階・直線壁・扉／窓の既存モデルを使い、曲線壁・開き勝手・自動室認識は追加しない。

状態・操作は `use-room-planner.js`、編集UIは `drawing-workspace.jsx` と `floor-plan-editor.jsx`、構造データの保存は `drawing-document.js` に配置する。画像解析と実寸補正は `floor-plan-importer.jsx` に保ち、変換した図面と端末内の下絵だけを親へ渡す。

## 保存と復元の境界

| 対象 | 保存先・形式 | 契機 |
| --- | --- | --- |
| 2D図面の形状 | `syncterior.drawing`、`{version:1,plan,drawingId?}` | 「図面を保存」の明示操作 |
| 図面ファイル | 同じJSON形式、1MB以下 | 書き出し・読込の明示操作 |
| 3Dの個人家具配置 | 既存`syncterior.personal-room`の第1/2版 | `room-session`の個人操作通知 |
| 下絵・表示設定・履歴・生成メッシュ | 保存しない | 画面内だけ |

図面だけの保存・読込で個人家具配置を上書きしない。保存した図面がなければ、既存の個人配置のcustom形状を初期値として使う。初期読み込みだけでは新しいキーへ保存しない。独立図面は家具を含まず、家具の位置・回転・色・寸法は従来の配置保存で維持する。

「図面から3Dを表示」は現在の図面を検証して既存のcustom形状へ適用する。3D配置は従来どおり個人保存するが、独立図面の保存は代行しない。3Dへ反映後に図面を編集・保存しただけでは、反映済みの配置は変わらない。もう一度明示反映する。

元図面IDが同じ場合は家具の実寸・位置を維持し、収まらない形状変更は3Dへ反映しない。新規作成・別画像・別図面のIDなら、以前の家具を引き継がず家具なしで生成する。図面の形状が有効なら、その図面だけの保存は可能。プリセットから生成する場合は家具のないcustom間取りになる。家具を含む複数案管理は#54の残作業。

単一図面のブラウザ内保存とJSON入出力を実装する。サーバー上の図面一覧・所有権・独立図面CRUD・複数案の履歴は未実装。バックエンドの形状共有はBE-11 / #43で追跡し、共有API・テスト専用APIの契約は変更しない。

## UIと編集の保護

- 個人編集は図面モードを初期表示し、共有リンクは3D・家具配置を開く。共有中は図面モードを無効にする。
- 作図を主役にし、ファイル操作・新規作成・画像変換と、図面名／高さを折りたたむ。
- 2点で壁を追加し、壁1本と付属する開口を削除できる。グリッドは通常0.25m、4目盛ごとに太線で、大きい図面は間隔を広げる。自動吸着はしない。
- 編集中の図面はモード切替で維持する。保存していない変更のある図面を新規作成・読込・変換で置き換える場合は確認する。離脱時はブラウザ標準の確認を要求する。
- 保存・JSON読込・書き出しは版と形状を検証し、保存失敗でも編集とファイル書き出しを継続する。
- 下絵・ファイルの古い読み込み結果を差し替え後やアンマウント後に反映しない。画像変換Workerの中止・差し替えは従来のAbortController経由で終了する。
- 図面の局所Undo/Redoは最大100操作で、保存・モード切替を越える永続履歴はない。Esc・キャンセル・blurで途中の操作を戻す。

## 別図面の取り込みで3Dが開けない不具合の修正

生成時に無条件で`preserveItems=true`としていたため、別の図面にも前の家具の床・壁判定を適用し、3D生成を拒否していた。図面の保存とJSONに任意の`drawingId`、custom個人配置の第2版エンベロープに任意の元図面IDを加える。保存形式の版と従来のキーは維持し、IDはroomモデル・共有snapshotへ混在させない。

別画像の変換・新規作成ではUUIDを新規発行する。再解析・実寸補正・手直しは同じ図面のIDを維持する。JSONのIDはファイル往復でも維持し、IDなしファイルは新しい図面として扱う。旧個人配置は元形状から安定した移行用IDを生成し、図面を保存しただけでは家具配置を上書きしない。同じ図面の修正では不正な反映を拒否し、別図面の置換は明示的な3D表示時だけ行う。画面にもどちらの動作になるか表示する。

回帰検証は`drawing-replacement.spec.js`で、別画像の解析→保存→再読込→3D生成、同じ図面の補正と再読込後の家具保護、JSONファイルの別図面／同図面の区別を両画面幅で行う。`drawing-mode.3d.spec.js`でも、前の家具が新しい床からはみ出す条件で別画像を実WebGLへ生成する。
